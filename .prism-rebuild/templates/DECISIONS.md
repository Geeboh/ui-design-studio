# Rebuild decisions

Record decisions that change behavior, scope, compatibility, cost or verification. Routine coding details can remain in the diff and task notes. Keep superseded decisions with a replacement link instead of rewriting history.

## DEC-001 — Replace with the decision title

### Evidence and constraints

State the observed problem, current repository/host facts, relevant user preferences, source references and uncertainty. Distinguish a factual source claim from a project policy or proposed implementation choice.

### Decision

Describe the exact chosen behavior and its scope. Include any effect on migration, public aliases, approval currentness, money, provider identity or release qualification.

### Alternatives and tradeoffs

Compare plausible options briefly. Explain why the chosen scope is sufficient and which future signal would justify revisiting it. Do not add infrastructure for a scale or deployment the product does not need.

### Validation and recovery

List acceptance cases, affected tests, evidence, rollback constraints and the next concrete action. Record genuine approvals only when the session actually supplied them. Do not turn an agent recommendation into user authority.
