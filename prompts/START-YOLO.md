# Start an autonomous UI redesign

Paste the following into a normal OMP session in the target project. Replace `models=auto-models` with `models=current-model` to keep the active model and reasoning selection for all specialist workers.

```text
Read .omp/skills/ui-design-studio/SKILL.md and run the complete UI Design Studio workflow for this repository.

Run mode=yolo with models=auto-models. Scope: the complete existing UI, every discovered page, dialog and applicable state.

Read and follow the project's applicable instructions, requirements, architecture decisions, existing design system and source. Record the actual context and source references. No profile selection is needed. Preserve the current project workflow, Git policy, unrelated work and previously established user preferences. Discover available model routing and verify the assignments actually used.

I delegate the aesthetic decisions to you. Perform the assessment and usability report. Use specialist agents to develop coherent visual directions, inspect their rendered concepts, choose or reconcile the strongest direction, and choose a suitable theme name. Have an independent critic challenge the decision and record the rationale as agent-yolo approval.

Create and inspect complete full-page/dialog mockups. Approve them only after checking agreed coverage, applicable responsive/states, interactions, accessibility, consistency and implementation cost. Direct coding agents to integrate the design and a versatile theme interface, obtain independent review, fix defects and complete the package and documentation.

Prefer code-native styling, small vectors and the existing component/dependency stack. Use the included theme contract for compatible web projects and establish an appropriate verified adapter for other UI stacks. Respect requirements for offline use, performance, accessibility, recovery and product behaviour. Measure actual bytes and runtime behaviour; do not invent tests, screenshots or user research.

The first successfully finalized Studio theme becomes the default with prior styling recoverable. On later runs, absent a specific instruction or established reason, create a new named module and retain the current default. Record this decision without asking me to choose.

Continue through Assess, Plan, Design, Produce and Finalize. Do not pause for preferences, concept selection, mockup approval, naming or routine implementation. Complete independent work while resolving blockers. Report only genuine missing inputs/access or unresolved required failures that prevent completion. Existing tool permissions and project Git/release rules still apply.

Persist current context, routing, decisions, coverage, evidence and blockers. Finish with the theme name/version, package and preview, actual changes, verification evidence, default status, known limitations, customization guide and rollback procedure.
```
